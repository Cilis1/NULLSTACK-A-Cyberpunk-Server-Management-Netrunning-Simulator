# Back Room: early-access scenario

This intentionally small standalone scenario (windowed on Windows, terminal-based on Linux) is a first playable slice, not the campaign or M0–M9 completion. You start with 800 credits, one server and a two-unit circuit. Each successful action is one day; rent and equipment overhead are charged after the action. Host to gain income and reputation, buy servers and circuit capacity, cool or repair the rack, or attempt risky intrusions. Once you have two servers and two reputation, the Archivists offer higher-paying preservation work that adds more legal heat and requires 50% condition. The Windows game window shows actions and objectives; on Linux, `help` explains the commands and exact victory and loss conditions.

Hosting and archive work heat and wear the rack; other activities let it cool toward 24 C. Cooling lowers the loaded equilibrium temperature. Above 45 C, thermal throttling lowers income and adds wear; active workloads also add 8 credits per server to the daily bill. This is an abstract aggregate model, not the per-tile physical simulation in the design. Intrusion is a single seeded risk roll, not the planned network minigame. Heat does not decay except through `laylow`. There are no effects or audio. Version 0.2 provides one manual save slot: on Windows, use Save Run and Load Run; on Linux, use `save` and `load`. Saving is not automatic. Windows stores the slot in `%APPDATA%\Nullstack\saves\back-room.sqlite`; Linux uses `back-room.sqlite` in the current working directory. Settings and mods are not implemented. The Windows installer is documented separately. Its hardcoded rules are temporary; the planned data-driven content architecture is not implemented.
